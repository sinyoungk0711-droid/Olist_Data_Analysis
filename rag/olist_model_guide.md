# Olist 모델 설명서

## M00 모델 파일 한눈에 보기
STEP1 노트북에서 학습한 모델은 model 폴더에 저장한다. 웹앱(Streamlit 대시보드)에는 pkl 4개를 쓴다: part6_recommend.pkl(상품 추천), part7_1_sentiment_ml.pkl(리뷰 감성), part8_seller_segment.pkl(판매자 유형), part9_seller_churn.pkl(판매자 이탈). 딥러닝 감성 모델(part7_2_sentiment_model.keras + part7_2_tokenizer.pkl)은 TensorFlow 설치가 무거워 웹앱에서 빼고 Colab 데모에서만 쓴다. BERT(07_3)는 파일로 저장하지 않는다. pkl은 학습한 scikit-learn 버전(1.6.1)과 같은 버전에서 불러와야 하므로 requirements.txt에 버전을 고정하고, 내 컴퓨터에서는 Python 3.12 가상환경을 쓴다.

## M06 상품 추천 모델 (part6_recommend.pkl)
하는 일: 상품 하나를 고르면 같은 카테고리에서 특징이 가장 비슷한 상품 5개를 찾는다. 방법은 KNN(가장 가까운 이웃 찾기)이다. 비교하는 특징은 가격, 무게, 길이, 높이, 너비, 사진 수, 평균 평점 7개이고, 로그로 바꾼 뒤 단위를 맞춰(스케일링) 거리를 잰다. 파일 안에는 scaler, 카테고리별 KNN 모델(knn_by_category), 상품 목록(products), 특징 이름(features), 추천 개수(k=5)가 들어 있다. 고객이 '함께 산 상품'이 아니라 '특징이 비슷한 상품'이다. 목록에 없는 새 상품은 추천할 수 없다(콜드 스타트). 실제 클릭·구매 효과는 A/B 테스트로 확인해야 한다.

## M71 리뷰 감성 머신러닝 모델 (part7_1_sentiment_ml.pkl)
하는 일: 포르투갈어 리뷰 문장을 넣으면 긍정 확률(0~1)을 돌려준다. 0.5 이상이면 긍정, 미만이면 부정으로 판정한다. 방법은 TF-IDF(단어마다 중요도 점수 매기기) + 로지스틱 회귀다. 파일 안에는 tfidf(단어 점수표 만드는 도구)와 model(로지스틱 회귀)이 함께 들어 있다. 학습 정답은 별점으로 만들었다(4~5점 긍정, 1~2점 부정, 3점 제외). 포르투갈어로만 학습해서 한국어·영어 문장은 아는 단어가 없어 결과가 의미 없다. 별점과 내용이 다른 리뷰(별점은 높은데 불만)를 찾는 데 쓸 수 있다.

## M72 리뷰 감성 딥러닝 모델 (part7_2)
하는 일: 머신러닝 모델과 같은 일을 딥러닝(Embedding)으로 한다. 모델 본체는 part7_2_sentiment_model.keras, 단어집은 part7_2_tokenizer.pkl에 따로 저장한다. 불러올 때 문장 길이를 학습 때와 같은 50단어(MAX_LEN=50)로 맞춰야 한다. 정확도는 머신러닝 모델과 거의 같지만 TensorFlow가 필요해 웹앱에서는 쓰지 않는다.

## M73 BERT 감성 분석 (07_3)
하는 일: 이미 학습된 다국어 BERT 모델을 추가 학습 없이 바로 써서 리뷰 감성을 판정한다. 별점 기반으로 직접 학습한 모델보다 정확도가 낮고, 중립(neutral)으로 답하는 경우가 있다. 모델 파일이 수백 MB라 저장·배포하지 않는다. 학습 데이터 없이 바로 쓸 수 있다는 장점을 보여 주는 비교용이다.

## M08 판매자 유형 모델 (part8_seller_segment.pkl)
하는 일: 판매자 숫자 5개로 4가지 유형(핵심 우량, 신규 성장, 휴면, 저평점 위험) 중 하나를 정한다. 방법은 K-Means 군집(정답 없이 비슷한 판매자끼리 4묶음)이다. 숫자 5개는 주문 건수, 판매액, 마지막 판매 후 지난 날 수, 첫 판매 후 지난 날 수, 평균 리뷰 점수다. 주문 건수와 판매액은 로그로 바꿔서 쓰고, 리뷰가 없는 판매자는 학습 때 중앙값(review_fill)으로 채운다. 파일 안에는 scaler, kmeans, names(묶음 번호 → 유형 이름), review_fill, features, cutoff(2018-06-01)가 들어 있다. 유형 이름은 사람이 묶음의 특징을 보고 붙인 것이다. 관리 방향은 핵심 우량은 우수 판매자 혜택·이탈 방지, 신규 성장은 온보딩 지원, 휴면은 재활성화 캠페인 또는 정리, 저평점 위험은 출고 마감 준수 관리와 품질·배송 점검이다.

## M09 판매자 이탈 모델 (part9_seller_churn.pkl)
하는 일: 최근 판매한 판매자가 앞으로 3개월 동안 주문을 한 건도 못 받을 확률(이탈 확률)을 계산한다. 이탈은 실제 폐업이 아니라 '다음 3개월 유효 주문 0건'이라는 실습용 정의다. 방법은 빈칸 채우기(중앙값) + 단위 맞추기 + 로지스틱 회귀(class_weight=balanced)를 한 묶음(Pipeline)으로 저장한 것이다. 판단에 쓰는 숫자는 14개다: 마지막 판매 후 일수, 첫 판매 후 일수, 판매한 달 수, 주문 수·판매액·주문당 금액(로그), 평균 배송 일수, 도착 지연율, 출고 지연율, 평균 리뷰, 1~2점 리뷰 비율, 최근 3개월·그 전 3개월 주문 수(로그), 주문 증감. 이 숫자들은 주문 기록 전체를 모아 계산해야 해서, 10 노트북에서 판매자 표(seller_table.csv)로 미리 만들어 두고 웹앱은 표를 읽어 예측한다(배치 예측). 확률 0.5 이상이면 이탈 위험으로 본다. balanced 설정은 이탈 판매자를 놓치지 않는 쪽(재현율↑)으로 학습한 것이라, 실제 이탈률보다 많은 판매자가 위험으로 잡힌다(정밀도↓). 담당자가 연락할 수 있는 인원이 정해져 있으면 예상 손실(이탈 확률 × 최근 3개월 판매액) 순서로 줄을 세운다.

## M10 분석 결과를 전략으로
재구매 3%라 성장이 신규 고객에만 의존한다 → 상품 추천(M06)으로 상품 페이지·장바구니에 비슷한 상품을 보여 추가 구매를 유도하고, 추천 클릭률·주문당 상품 수·객단가로 확인한다. 배송 지연이 리뷰를 떨어뜨린다 → 감성 모델(M71)로 부정 리뷰를 자동 분류해 CS팀이 먼저 대응하고, 부정 리뷰 응답 시간·재리뷰 평점으로 확인한다. 지연·저평점이 일부 판매자에게 몰린다 → 판매자 유형(M08)별로 관리하고, 유형별 출고 지연율·평균 평점으로 확인한다. 판매자가 떠나면 상품 구색과 매출이 줄어든다 → 이탈 모델(M09)의 예상 손실 순서로 담당자가 연락하고, 3개월 뒤 실제 이탈률과 유지된 판매액으로 확인한다. 모델은 2018-06 시점 데이터로 학습했으므로 3개월마다 새 데이터로 다시 학습하고 성능을 비교해야 한다.
